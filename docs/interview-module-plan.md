# 面试模块（Interview Hub）设计

> 状态：**P1、P2、P3 已上线**（2026-10-16）
> 目标仓库：前端 `aiblog-web`（`/home/ubuntu/aiblog-web`）+ 后端 `aiblog-java`（`/home/ubuntu/aiblog-java`）
> 相关：`docs/ai-community-plan.md`（AI 广场，已上线）、`docs/ai-features-proposal.md`
> 依赖 skill：`aiblog-web-ui`（颜色令牌 / 排版 / 卡片与两栏规范）

---

## 0. 一句话

在博客与 AI 广场之外新增**第三个一级栏目「面试」**，三期递进：
**P1 面试题库 + 公司库（A）→ P2 个人备战台（C）→ P3 AI 模拟面试（B）**。

**核心论点：三期共用同一套数据骨架（题目 × 公司 × 岗位 × 轮次），所以先做 A 是"打地基"，而不是"分期付款"。**
C 的复习卡片、B 的模拟出题，本质上都是对同一批题目做不同投影；反过来先做 B 会因为没有题源而空转。

## 1. 定位与边界

### 1.1 建议默认决策（boss 未拍板的点，先按此设计，返工成本低）

| 议题 | 建议 | 理由 |
| --- | --- | --- |
| 栏目形态 | **并列一级栏目**，路由 `/interview`，前台名「面试」 | 与「博客」「AI 广场」同级；不塞进首页板块（会失去可检索/可筛选/可排行） |
| 维度 | **公司 × 岗位 双维度都做**（公司可空 = 通用题） | 只按公司会漏八股，只按岗位无法做"目标公司"筛选 |
| 面经长文 | **不建新内容表**，复用 `articles` + 新增分类「面经」 | 正文、评论、SEO、后台编辑器、封面全部现成 |
| 题库录入 | P1 **仅管理员录入**，表结构预留 `submitter_id` / `status` | 冷启动质量可控，UGC 审核后置，不返工 |
| AI 评分（B） | **不把 LLM key 落到博客后端**：复用已有 `api_keys`，由 pi agent 调用回填评分 | `aiblog-java` 目前**没有任何 LLM 客户端**；绕开密钥托管与费用风险 |
| 与 AI 广场关系 | 完全独立的表，不混用 `ai_items` | `ai_items` 的语义是工具目录，字段（platform/install）对不上 |

### 1.2 明确不做（本期）

- 不做在线代码判题（Judge）与沙箱执行
- 不做付费题库 / 会员墙 / 交易
- 不爬取整站面经正文（只存题目 + 原创解析 + `source_url` 出处链接）
- **不改动** `articles` / `comments` / `tags` / `users` 表结构（只新增表 + 复用 `tags` 关联表模式）

## 3. 数据模型

沿用现有约定：`id` 主键、`created_at`/`updated_at`、**软删除 `deleted_at`（手动管理）**、枚举存 `VARCHAR`、迁移文件 `src/main/resources/db/migration/V<日期>__<名>.sql` + 同步更新 `schema.sql`。

### 3.1 P1：`interview_companies`

```sql
CREATE TABLE IF NOT EXISTS interview_companies (
    id         BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    slug       VARCHAR(80)  NOT NULL UNIQUE,
    name       VARCHAR(120) NOT NULL,
    industry   VARCHAR(60),
    scale      VARCHAR(40),
    logo_url   VARCHAR(400),
    intro      TEXT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    deleted_at TIMESTAMP
);
```

### 3.2 P1：`interview_questions`（核心表，三期共用）

```sql
CREATE TABLE IF NOT EXISTS interview_questions (
    id            BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    slug          VARCHAR(160) NOT NULL UNIQUE,
    company_id    BIGINT,                    -- 可空：通用题
    position      VARCHAR(80),               -- 岗位族：java / frontend / algo / product ...
    round         VARCHAR(40),               -- 笔试 / 一面 / 二面 / 三面 / hr
    difficulty    SMALLINT DEFAULT 3,        -- 1~5
    question_type VARCHAR(30) NOT NULL,      -- concept / system / algorithm / coding / project / hr
    title         VARCHAR(240) NOT NULL,
    body          TEXT NOT NULL,             -- 题干（markdown）
    answer        TEXT,                      -- 参考答案，前台默认折叠
    follow_ups    TEXT,                      -- 追问链（JSON 数组字符串）
    source_url    VARCHAR(500),              -- 出处标注，不镜像正文
    asked_year    SMALLINT,
    star_count    INT DEFAULT 0,
    view_count    INT DEFAULT 0,
    status        VARCHAR(20) DEFAULT 'pending',  -- pending / published / rejected
    submitter_id  BIGINT,
    created_at    TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at    TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    deleted_at    TIMESTAMP
);
CREATE INDEX IF NOT EXISTS idx_iq_hot     ON interview_questions (star_count DESC, view_count DESC);
CREATE INDEX IF NOT EXISTS idx_iq_facet   ON interview_questions (position, round, difficulty);
CREATE INDEX IF NOT EXISTS idx_iq_company ON interview_questions (company_id);

CREATE TABLE IF NOT EXISTS interview_question_tags (
    question_id BIGINT NOT NULL,
    tag_id      BIGINT NOT NULL,
    PRIMARY KEY (question_id, tag_id)
);

CREATE TABLE IF NOT EXISTS interview_question_marks (   -- 标记掌握 / 收藏
    question_id BIGINT NOT NULL,
    user_id     BIGINT NOT NULL,
    level       VARCHAR(20) DEFAULT 'marked',  -- marked / fuzzy / mastered
    created_at  TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (question_id, user_id)
);
```

`tags` 表直接复用（和 `article_tags` / `ai_item_tags` 同构），不新建标签表。

### 3.3 P2：个人备战台

| 表 | 关键列 |
| --- | --- |
| `interview_plans` | `user_id` / `target_company_id` / `position` / `interview_date` / `status` |
| `interview_review_cards` | `user_id` / `question_id` / `stage`(0-5) / `due_at` / `last_result` / `lapses` |
| `interview_applications` | `user_id` / `company_id` / `position` / `stage`(投递/笔试/一面…/offer) / `applied_at` / `note` |

SRS 只做 6 档固定间隔（1d / 2d / 4d / 7d / 15d / 30d），**不引入 SM-2 参数**，够用且好调试。

### 3.4 P3：AI 模拟面试

| 表 | 关键列 |
| --- | --- |
| `interview_sessions` | `user_id` / `company_id` / `position` / `round` / `mode`(text) / `status`(created/ongoing/scoring/done) / `score` |
| `interview_session_questions` | `session_id` / `question_id`(可空，AI 生成时为空) / `generated_title` / `seq` |
| `interview_answers` | `session_id` / `seq` / `answer_text` / `score` / `feedback`(JSON) |
| `interview_reports` | `session_id` / `overall_score` / `dimensions`(JSON: 准确性/深度/表达/结构) / `suggestions` |

**评分链路（关键设计）**：前端提交 → 后端落 `status='scoring'` → pi agent 通过已有 `api_keys` 拉取待评会话 → 调用模型（走 `~/new-api` 网关）→ `POST /api/interview/sessions/{id}/evaluate` 回填。
好处：博客后端零 LLM 依赖、零密钥、评分 prompt 可随时改而不用重发版。
代价：评分是异步的，前端需要轮询（复用现有 2s 轮询模式即可）。

## 6. 分期与验收

| 阶段 | 内容 | 预估 | 验收标准 |
| --- | --- | --- | --- |
| **P1（A）** | 公司库 + 题库（前台 4 页、后台 2 页、6 个接口、3 张表） | 2~3 天 | 后台录入 10 题 → 前台可按岗位/公司/难度筛出、详情可看答案、`/interview` 在工作台导航可进 |
| **P2（C）** | 备战台 + SRS 复习 + 投递追踪 | 2~3 天 | 登录用户建计划 → 复习页出到期卡片 → 三键反馈后 `due_at` 正确推移 |
| **P3（B）** | 模拟面试 + 异步评分报告 | 1~2 周 | 生成 5 题会话 → 逐题作答 → 2 分钟内出维度分与建议 |

**冷启动**：P1 上线后用 pi agent 从现有文章 + 公开面经批量生成题目**草稿**（`status='pending'`），人工过审后发布，避免"空库上线"。

**门禁（提交前必跑）**：
- `aiblog-web`：`pnpm test` + `pnpm test:node` + `pnpm build`
- `aiblog-java`：`mvn -q test`，Flyway 迁移在 dev 库先跑一遍（当前 4 个迁移文件，新增 `V20261016_1__interview_hub.sql`）
- 提交信息：`feat(interview): 新增面试题库与公司库`（一次提交只做一类改动）

## 7. 风险与开放问题

| 风险 | 应对 |
| --- | --- |
| 内容冷启动慢 | agent 生成草稿 + 人工过审；先导入 50 题打出可用度 |
| 版权 / 隐私（面经含真实面试信息） | 只存题目与原创解析，长文一律 `source_url` 外链；公司名做中性化处理 |
| 与 `ai_items` 概念混淆 | 独立表独立路由；首页只放一条入口，不做交叉推荐 |
| P3 异步评分失败 | `status='scoring'` 超时 10 分钟回退 `failed` 并允许重评，避免卡死 |
| 题库被爬 | `view_count` 统计 + 详情页对未登录用户限流（复用现有 Redis） |
