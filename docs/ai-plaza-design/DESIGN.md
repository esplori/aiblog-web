## 2. 设计目标与三条原则

1. **先给判断依据，再给安装方式。** 用户来这里的第一个问题是「这东西敢不敢装、在我在的客户端上能不能跑」——所以风险徽章在卡片层级就要可见，兼容性在详情页要排在安装说明之前。
2. **结构化字段优先于正文。** 平台、传输方式、许可、版本要求都是字段，不该埋在自然语言里。
3. **克制。** 全站是浅色阅读型站点，广场不能变成炫技展台：只用品牌蓝 + 两套固定语义色板，动效只有 2px 上浮与 200ms 过渡。

### 3.1 沿用（不新增）

| 令牌 | 值 | 来源 |
| --- | --- | --- |
| 品牌主色 | `--color-brand: #2563eb`（可换肤） | `app/assets/css/main.css` |
| 品牌色阶 | `brand-50…900`（color-mix 生成，只 11 档） | `tailwind.config.js` |

| 容器 | 1200px | `.container` |
| 文字 | `#111827 / #6b7280 / #9ca3af` | 现有 Tailwind gray 用法 |

### 3.2 新增：类型语义色（5 类）

| 类 | 主色 | 底色 |
| --- | --- | --- |
| Skill | `#2563eb` | `#eff6ff` |
| MCP | `#7c3aed` | `#f5f3ff` |
| 提示词 | `#0891b2` | `#ecfeff` |
| 模型 | `#d97706` | `#fffbeb` |
| 工具 | `#475569` | `#f1f5f9` |

### 3.3 新增：风险语义色（4 档）

| 档 | 色 | 语义 | 展示规则 |
| --- | --- | --- | --- |
| `read` 只读 | `#047857` | 只读取文件/数据 | 默认档 |
| `write` 可写 | `#b45309` | 会创建或修改文件 | |
| `net` 联网 | `#1d4ed8` | 会访问外部网络 | |
| `exec` 执行 | `#b91c1c` | 会在本机启动进程 | **详情页常驻警示条** |

> ⚠ **类型色与风险色不随品牌换肤**——它们是语义色，换肤时语义必须稳定。落地时登记进 `tailwind.config.js` 的 `theme.extend.colors`（新增 `type.*` 与 `risk.*` 两组），**不要**用改 `brand-*` 的方式实现。

### 3.4 其他

- 字体：继承全站 `-apple-system / PingFang SC` 栈；代码与客户端名用等宽字体。
- 圆角体系：卡片 16 / 中件 10 / 小件 8 / 胶囊 999。
- 动效：`200ms ease`，只用于 hover、Tab 指示条、骨架屏；不做入场动画（列表滚动性能优先）。

## 5. 逐屏说明

### 5.1 01 · 广场列表

- **页面头**：标题 + 一句定位说明 + 4 个数字（收录 / 平台 / 报告 / 本周新增）+ 双 CTA（导出配置、提交条目）。
- **类型 Tab**：全部 / Skill / MCP / 提示词 / 模型 / 工具，右侧带计数。指示条 2px 品牌色。
- **筛选左栏**：平台勾选（带计数）→ 权限风险（4 档胶囊）→ 热门标签 → 清空。**风险筛选默认隐藏「执行」档**，这是安全默认值。
- **卡片网格**：2 列。卡片结构：类型徽章 + 风险徽章 + 实测状态 → 名称 + 作者 → 一句话（2 行截断、固定高度保证对齐）→ 平台 chips → 页脚（★ / 实测数 / 更新时间 / 查看）。
- **右栏**：本周热门 Top5（带名次与本周增量）→ 最新实测报告（用 ✓ / ! / ✕ 直接暴露结论）→ 导出配置 CTA 卡。
- **列表视图**（网格/列表切换）：列表态为 32px 图标 + 单行信息 + 右侧投票数。

### 5.2 02 · 条目详情

信息顺序是这一屏的核心设计决策：

1. 面包屑
2. 标题区（名称 + 仓库 + 徽章 + 元信息 + 投票/收藏/分享）
3. **风险警示条（仅 exec 级）**
4. 安装（平台 Tab + 文件路径 + 深色代码块 + 复制）
5. 能力说明（含「不适合的场景」——反向信息提升可信度）
6. **兼容性矩阵**
7. 实测报告（含「我实际跑通的片段」）
8. 右栏：条目信息 / 标签 / 相关条目 / 纠错举报

### 5.3 03 · 清单

编辑精选用 2 格宽大卡（左侧数字封面），其余 3 列常规卡，末尾一个虚线「创建我的清单」占位卡。

### 5.4 04 · 提交条目

四步条（基本信息 / 安装与兼容 / 风险声明 / 预览提交）。三个设计要点：

- **类型用卡片单选**而不是下拉——选错类型是最高频的提交错误；
- **风险声明用可勾选卡片**，并写明「漏报风险会被直接驳回」；
- **右侧常驻预览 + 提交检查**：字段错误定位到具体项，而不是等提交后弹 toast。

### 5.5 05 · 后台

沿用现有后台（`layouts/admin`）的侧边栏与 Element Plus 表格语言。AI 广场作为一级菜单 + 3 个子项（条目管理 / 实测报告 / 清单管理），「实测报告」带待处理红色角标。待审核行用浅黄底并置顶；批量操作在勾选后出现在筛选栏。

### 5.6 07 · 移动端

只做三件事：看、搜、复制。详情页顺序重排为「风险 → 能不能用 → 怎么装」；筛选降级为底部抽屉；安装代码块横向滚动、不折行。

## 6. 交互与状态规范

| 场景 | 行为 |
| --- | --- |
| 复制安装片段 | 成功后按钮变「✓ 已复制」，2s 后还原；剪贴板不可用时降级为全选文本并提示手动复制 |
| 投票 | 乐观更新（先 +1，失败回滚并 toast）；未登录时文案改为「登录后投票」并跳登录 |
| 筛选 | 即时生效，同步 URL 查询参数（可分享、可回退）；无结果落到空态 |
| 加载 | 列表用骨架卡而不是转圈；详情标题区优先渲染，正文分块加载 |
| 空态 | 三种：筛选无结果 / 广场刚上线 / 接口失败。**三者文案与动作各不相同**，见 06 页 |
| 风险提示 | `exec` → 详情页常驻条；`net` + `exec` 同时在列表卡片上也不折叠 |
| 键盘可达性 | 卡片是 NuxtLink（天然可 Tab）；风险徽章带 title 与屏幕阅读文本；Tab 组件支持左右方向键 |
| 对比度 | 徽章文字与其 8% 底色对比度 ≥ 4.5:1；避免纯色底 + 白字的 12px 文本 |

## 7. 实施映射（设计稿 → 代码）

| 设计稿 | Vue 组件 | 关键约定 |
| --- | --- | --- |
| 卡片 | `app/components/ai/ItemCard.vue` | `rounded-2xl border border-gray-200` + hover 上浮 2px、边框转 `brand-200` |
| 类型徽章 | `TypeBadge.vue` | 走新增 `type.*` 色；保持 `h-[22px] px-2.5 text-xs rounded-full font-semibold` |
| 风险徽章 | `RiskBadge.vue` | 走新增 `risk.*` 色；四档可叠加 |
| 安装块 | `InstallBlock.vue` | 深色块用固定 slate 值，不要用 `bg-gray-900`（换肤时不跟随） |
| 兼容矩阵 | `CompatMatrix.vue` | 数据来自 `ai_reports` 聚合；无报告的版本不渲染 |
| 投票 | `VoteButton.vue` | 乐观更新 + 失败回滚 |
| 导出 | `ExportDialog.vue` | 纯前端拼装，无接口 |
| 提交表单 | `app/pages/ai/submit.vue` | 注意**禁用 `defineModel`**，用 props + emits；类型卡片单选用受控组件 |
| 后台 | `app/pages/admin/ai-items.vue` | 抄 `admin/tags.vue` 的表格 + 弹窗模式；菜单驱动权限，无需额外代码 |

实施注意（来自 `aiblog-web/AGENTS.md`）：

- 颜色一律走 `brand-*`（只 11 档，写 `brand-950` 不报错但静默失效）；类型/风险色走新增固定语义色。
- 站名与广场名走 `useSiteConfig()`，不写死字符串。
- `app/utils/**` 不参与 Tailwind content 扫描，md 渲染器里不要写类名。
- 列表与详情用 `useAsyncData` 走 SSR（SEO 是加这个模块的主要非功能收益）。

| 位置 | 口径 | 反例 |
