# MVP 实施建议（工作台 v2 + AI 广场）

> 2026-10-15｜前置：`v2/DESIGN-v2.md`（工作台）、`../DESIGN.md`（AI 广场）、`../../ai-community-plan.md`（数据模型）
> 结论先行：**MVP = 一套外壳 + 两个模块的最小可用版本，共 7 个任务、约 6 人日**；投票/报告/评论/清单/⌘K/暗色全部延后。

---

## 1. MVP 的边界（做完这些就算「能用」）

登录后进工作台 → 看到「继续阅读 + 最新文章 + AI 热门 + 待办」，左侧可切到 AI 广场 → 广场能按类型筛、能看条目详情（含风险与安装片段）→ 后台能录入条目 → 未登录访客看到的是公开内容页。

---

## 2. 三条关键决策（建议，直接影响工作量）

### 决策一：工作台私有，AI 广场公开 —— 顺便解决 SEO 问题

| 路由 | 可见性 | 理由 |
| --- | --- | --- |
| `/`（工作台） | **仅登录**；未登录 302 → `/articles` | 工作台是个人任务起点，本来对陌生访客无意义 |
| `/articles` `/post/[uuid]` | 公开 SSR | 现有内容页，搜索引擎的主要入口 |
| `/ai` `/ai/[slug]` | **公开 SSR** | 长尾落地页，是这个模块最重要的非功能收益 |

这样把「工作台式首页伤 SEO」的问题直接绕开：**对外可爬的仍是内容页与条目页**，工作台只是登录后的门厅。比 v2 §6 里的 A/B/C 都省事，也符合直觉。

### 决策二：AI 模块 MVP 只建 3 张表，但字段一次到位

- 建：`ai_items` / `ai_item_targets` / `ai_item_tags`
- 不建（P1 再加，表结构已在设计里定好）：`ai_item_votes` / `ai_reports` / `ai_item_comments` / `ai_collections*`
- 但 `ai_items` 的 `star_count` / `report_count` / `status` / `featured` 字段**现在就加上**，P1 只补表和接口，不再动主表
> 好处：迁移只做一次，避免「上线两周再改表」。

### 决策三：后台零新增权限代码

AI 广场作为 `menus` 表里的一条一级菜单 + `role_menus` 授权，直接复用现有「菜单驱动权限」与 Element Plus 表格/弹窗模式（抄 `admin/tags.vue`）。

## 3. 任务分解（按执行顺序，T4 可与 T2/T3 并行）

| # | 任务 | 产出 | 依赖 | 预估 |
| --- | --- | --- | --- | --- |
| T1 | 备份与回滚准备 | 旧镜像打 `rollback-*` tag；PG 备份一份 | — | 0.2 人日 |
| T2 | 工作台外壳 | `layouts/workbench.vue` + `utils/navModules.ts`（纯数据）+ 折叠态记忆 | — | 1 |
| T3 | 工作台首页 Bento | `/` 改造，数据全用现有接口（articles / categories / tags） | T2 | 1 |
| T4 | 后端 AI 只读接口 | 3 张表迁移 + 实体/Mapper/Service + 4 个 GET 接口 | — | 1.5 |
| T5 | 后台条目 CRUD | 菜单注册 + `admin/ai-items.vue`（表格 + 弹窗 + 发布/下架） | T4 | 1 |
| T6 | 前台 AI 模块 | `/ai` 列表（类型分段 + 筛选 + 卡片）+ `/ai/[slug]` 详情（风险条、安装块、信息卡） | T4 | 1.5 |
| T7 | 首页接入 + 部署联调 | Bento 里「AI 热门」接真实接口；后端镜像重建 + 前端重建；验收 | T3,T5,T6 | 0.7 |

**接口清单（T4 只做 4 个）**

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/ai/items` | 列表（`type/platform/tagId/keyword/sort/page/size`，只返回 published） |
| GET | `/api/ai/items/{slug}` | 详情（含 targets + tags） |
| GET | `/api/ai/hot` | 首页 Bento 用（size 默认 4–6） |
| GET | `/api/ai/stats` | 各类型计数（给类型分段上的数字） |

写接口只做后台需要的：`POST/PUT /api/admin/ai/items`、`POST /api/admin/ai/items/{id}/status`、`DELETE`。
安全配置：`GET /api/ai/**` 加入白名单（与 `/api/articles/**` 同一行风格）。

## 4. MVP 明确不做

⌘K 命令面板 · 暗色主题 · 通知面板 · 投票 · 实测报告（含兼容性矩阵的自动聚合）· 评论 · 清单 · 配置导出 · 文章内嵌 `[[ai:slug]]` · 移动端底部 Tab（只保证基本响应式可用）

> 兼容性矩阵在 MVP 里降级为：条目详情展示 `ai_item_targets` 里手填的「客户端 / 版本 / 是否验证」三列，不接报告聚合。

## 5. 验收清单（可逐条测）

1. 未登录访问 `/` → 跳到 `/articles`；登录后 `/` 显示工作台
2. 侧边栏切换「博客 / AI 广场」两个模块，面包屑与高亮正确；折叠后刷新仍保持折叠
3. 工作台「最新文章」「继续阅读」显示真实数据；AI 热门显示已发布条目
4. `/ai` 能按类型筛、按平台筛；`?type=mcp` 刷新后筛选保持（URL 即状态）
5. `/ai/[slug]` 显示风险徽章与安装片段；勾选「执行」的条目顶部有常驻警示
6. `/ai`、`/ai/[slug]` 未登录可访问，且 `curl` 能看到 SSR 出的内容（SEO 底线）
7. 后台能新建条目 → 列表可见 → 前台出现在 `/ai`；下架后前台消失
8. 种子数据：上线时至少 15 条（我按现有知识先录一批 MCP / Skill）
9. 部署后 `curl -f localhost:3000` 健康；无 500；前端 `pnpm test` + `pnpm build` 通过

## 6. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 后端要重建镜像 + 有库表变更（**非零迁移**） | T1 先打镜像 tag + 备份 PG；迁移全 `IF NOT EXISTS`，可重复执行 |
| 工作台首页改动大，可能拖垮首屏 | Bento 各块独立 `useAsyncData`，任一块失败只影响该块（降级为 skeleton） |
| 用户误以为「条目=可直接安装」 | 风险徽章 + 详情页警示条在 MVP 就上线（这是安全底线，不可延后） |
| SEO 回归 | 验收第 6 条用 `curl` 检查 SSR 输出；`/` 不参与索引（`noindex`） |
| 范围膨胀 | 本文 §4 就是「不做清单」，加进来要显式说明 |

## 7. 下一步

你回一句「开始」，我就按 **T1 → T4 → T2/T3 → T5 → T6 → T7** 的顺序做，每完成一个任务给你一条 20 行内的进展（含验收证据）。
若希望更快看到东西：也可以先做 T2+T3（纯前端、不碰数据库、不影响线上内容页），把工作台外壳先立起来给你看，再动后端。
