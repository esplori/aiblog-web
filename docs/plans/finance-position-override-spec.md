## 2. 数据模型

新增表 `fin_position_override`（覆盖层，不改流水）：

```sql
CREATE TABLE IF NOT EXISTS fin_position_override (
    id         BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    user_id    BIGINT NOT NULL,
    symbol     VARCHAR(16) NOT NULL,
    shares     INT NOT NULL,
    avg_cost   NUMERIC(14,3) NOT NULL,
    note       VARCHAR(200),
    deleted_at TIMESTAMP,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
CREATE UNIQUE INDEX IF NOT EXISTS uk_fin_pos_override
    ON fin_position_override (user_id, symbol) WHERE deleted_at IS NULL;
```

- 落库位置：`schema.sql` 追加（幂等 DDL，生产自动生效）+ `db/migration/V20261117_1__fin_position_override.sql`（同内容，归档）
- 无 `user_version` 机制（本项目不用），迁移编号按 `V<yyyyMMdd>_<n>__name.sql` 顺延
- 语义：一行代表「该 symbol 的手工持仓」，`shares` 可为 0（等于手工清仓）；软删即撤销

## 3. 接口

鉴权：均沿用 `SecurityUtil.getCurrentUserId()`，未登录返回 401。

### PUT /api/finance/positions/{symbol}

- 请求体：`{"shares": 600, "avgCost": 33.5, "note": "券商口径"}`（`shares` int，`avgCost` 3 位小数，`note` ≤200 字符，可空）
- 校验：`shares` ∈ [0, 100000000]；`avgCost` ∈ (0, 100000]，3 位小数四舍五入；`symbol` 走已有 `FinPortfolioService.normalize()`
- 语义：upsert（存在未删除的 override 则更新），返回覆盖后的 `FinPositionVO`；`shares=0` 时 `data` 为 `null`
- 成功：`{"code":200,"message":"ok","data":FinPositionVO}`

### DELETE /api/finance/positions/{symbol}

- 撤销覆盖（软删），回落流水推导；无覆盖时同样返回 200（幂等）
- 成功：`{"code":200,"message":"ok","data":null}`

### GET /positions、GET /summary

- 响应新增字段：`FinPositionVO.manual`（boolean，是否手工覆盖）、`FinPositionVO.note`（string，可空）
- 其余字段口径不变，只是数据源在推导结果之上套一层覆盖

错误码：

| 码 | 触发 | 用户可见文案 |
|---|---|---|
| 401 | 无 token / token 失效 | 请先登录 |
| 400 | shares < 0 或 > 1e8 | 股数需在 0 ~ 100000000 之间 |
| 400 | avgCost ≤ 0 或 > 100000 | 成本价需在 0 ~ 100000 之间 |
| 404 | symbol 既无持仓也不在 `fin_instrument` | 标的不存在，请先记一笔交易或加自选 |

## 4. 状态机 / 流程

```
流水推导持仓 ──┬─ 无 override ──────────────→ manual=false
               └─ 有 override(shares>0) ────→ manual=true，shares/avgCost 取 override
                 override(shares=0) ───────→ 该 symbol 不出现在持仓列表（手工清仓）

编辑持仓 → upsert override（manual=true）
撤销编辑 → 软删 override → 回到流水推导
新增交易（POST /trades）且该 symbol 存在 override → 自动软删 override，响应体 message 追加
   "已按新交易重置该股手工持仓"（避免用户的覆盖值和新流水打架）
```

非法转移的拒绝：对不存在且不在 `fin_instrument` 的 symbol PUT → 404（见上表）；对 `shares=0` 再 DELETE → 200 幂等。

## 5. 错误分支

| 触发条件 | 返回 | 前端文案 |
|---|---|---|
| 未登录 | 401 | 页面已有登录引导，弹窗保存按钮 disabled |
| 股数/成本非法 | 400 | 弹窗内红字「股数需在 0 ~ 100000000 之间」/「成本价需在 0 ~ 100000 之间」 |
| 标的不存在 | 404 | 「标的不存在，请先记一笔交易或加自选」 |
| 网络/后端 5xx | `ApiError` | 「保存失败，请稍后重试」 |
| `avgCost` 输入非数字 | 前端拦截 | 「成本价只能是数字」 |

## 7. 不做的范围

- 不支持编辑交易流水（`fin_trade` 仍只增/删）
- 不做手工现价 / 手工市值覆盖（508038 这类无行情标的仍会市值=0，另立规格）
- 不做多账户、导入导出、批量覆盖
- 不回写历史 `fin_daily_snapshot`
- 不做按生效日期的版本化覆盖（覆盖从保存时刻起生效）
- 不改卖出成本算法

## 8. 风险与回滚

- 风险：改股数会即时改变 `dayPnl`（= shares×(price−prevClose)）与 `weight`，属预期；当日收盘快照按新值写入，历史不回改
- 风险：卖空/负股数不支持（shares ≥ 0）
- 回滚：`DROP TABLE fin_position_override;` 并移除 `schema.sql` 中对应 DDL、撤掉两个接口与 `FinPositionVO.manual/note` 字段；流水数据全程未被修改，回滚后持仓自动回到纯推导口径
- 灰度：接口新增，不动既有接口语义，可先上线后端再上前端按钮
